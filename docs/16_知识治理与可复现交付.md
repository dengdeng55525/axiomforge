# 知识治理与可复现交付

AlgoForge 把能力知识和运行制品都当作可审计事实管理。能力卡进入图谱前经过来源、状态、版本、哈希和关系校验；一次运行结束后，代码、数据契约、验证结果和报告形成只读的制品证明。

## 能力知识质量闸门

质量闸门由 `src/capability_factory/knowledge_governance.py` 提供，核心入口是 `validate_snapshot` 和 `validate_store`。它不调用模型、不写数据库，适合本地命令、CI、API 和前端知识工作台共同使用。

每次检查包含以下事实：

- 来源记录必须有稳定 ID、URI、许可证、内容 SHA256 和定位信息。
- 能力版本必须从 `v1` 连续递增，内容哈希与规范化卡片一致，相同内容不能重复注册。
- `draft`、`extracted`、`verified`、`deprecated` 状态和两个任务类型使用固定词汇。
- 每张能力卡必须引用真实来源，并在图中形成 `DERIVED_FROM`、`SOLVES` 和版本 `SUPERSEDES` 关系。
- 边必须连接已存在的节点，关系类型来自白名单；悬空边、重复边和未知关系都会被定位。
- 空库、缺失来源、损坏 JSON、篡改卡片和版本跳号都有明确状态，不会被展示成满分通过。

本地检查命令：

```bash
python scripts/validate_knowledge.py \
  --database artifacts/knowledge.sqlite3 \
  --output artifacts/knowledge-quality.json
```

命令只读打开 SQLite。返回的 JSON 包含 `status`、`summary`、逐项 `checks`、`issues` 和 `warnings`，可直接作为 CI 工件。API `GET /knowledge/quality` 返回同一份结构，知识页按需加载，用户可以展开具体问题和关系证据。

## 运行制品证明

API `GET /runs/{run_id}/reproducibility` 对运行目录执行受限、只读的 SHA256 清单扫描。清单只包含四类证据：

1. `input`：数据快照与数据 manifest；
2. `code`：候选算法代码和每次修复尝试；
3. `validation`：构造计划、模型元数据和验证结果；
4. `report`：JSON、Markdown、HTML 报告和运行进度。

响应只返回运行目录相对路径、大小、哈希、声明的 `schema_version` 和完整性状态，不回显数据内容、绝对路径、LLM 请求响应、worker 日志或密钥。缺失、超限、符号链接、路径越界和哈希不匹配会使清单进入 `partial` 或 `failed` 状态，并保留具体原因。

报告页的“制品完整性”面板采用显式触发，避免在用户浏览历史报告时重复扫描大型文件。它适合代码审查、答辩复核和发布前检查；哈希清单证明文件一致性，运行结果仍需结合独立验证器、数据协议和模型卡判断。

## 任务产物边界

一次运行的目录结构如下：

```text
artifacts/runs/<run_id>/
├── dataset/                 # 数据 manifest 与 worker 输入
├── candidates/<id>/         # 每个候选的 attempt、model.py、verification.json
├── llm/                     # 受控运行制品，默认不进入公开 evidence bundle
├── progress.json
├── report.json
├── report.md
└── report.html
```

公开 evidence bundle 继续执行字段白名单、密钥扫描、路径相对化和源报告哈希校验。知识质量报告与制品证明都属于可复核的中间事实，前端默认折叠详细 JSON，结论、状态、来源和失败定位保持优先展示。

## 与 Agent 闭环的关系

Agent 只能提出能力卡和算法候选，结构化合约、知识闸门、受限执行器和独立评分器负责决定它们是否进入下一阶段。运行成功后，经过验证的失败修复经验写回 SQLite，并通过版本和来源关系参与后续检索。这样形成“来源 → 能力 → 方案 → 制品 → 验证 → 经验”的可追溯链路。
