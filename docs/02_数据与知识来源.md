## 2. 主场景的业务定义

目标：在发起一次营销联系前，基于可用客户属性和既往营销历史，给出订购倾向概率及联系优先级。y=yes 为正类。这不是信用违约、客户流失或营销因果效果预测。

主协议先采用保守的 10 个输入字段：age、job、marital、education、default、housing、loan、pdays、previous、poutcome。

以下字段不进入主协议：

- duration：本次/最后联系的实际通话时长；预测前不可取得，作为明确的业务泄漏禁用字段。
- campaign：统计包含当前联系；不能直接视为发起联系前已知的计数。
- contact、month、day_of_week：原数据描述与实际联系有关；如果业务有已知排程，可以另外定义“计划渠道/计划日期”协议，但不能自动替代。
- emp.var.rate、cons.price.idx、cons.conf.idx、euribor3m、nr.employed：不同频率的经济指标，公开数据没有完整的发布时点与可用时点记录。作为补充研究协议可以使用，主协议不宣称已完成 point-in-time 对齐。

保留 unknown 作为有意义的类别；pdays=999 表示此前未联系，不当作普通的极端天数填平。生产插件建议派生 previously_contacted 与 days_since_previous，并且只在训练集拟合变换。基线探针目前只是原字段的保守基线，这个派生逻辑仍待插件实现。

模型可输出风险/倾向排序，但不能声称提高了真实营销收入，也不能用观察性数据直接证明营销增量。若要估算净收益，单次联系成本和转化收益须由用户输入并明确标成情景假设。

## 3. Bank 划分和测试集纪律

官方描述该版本按日期顺序排列；CSV 没有完整时间戳和可靠客户唯一 ID。本项目保留原顺序，以行位置切分，不能编造具体某年某月的边界，也不能承诺客户级完全隔离。

- train：行位置 [0, 24712)，共 24,712 条。
- validation：行位置 [24712, 32950)，共 8,238 条。
- sealed test：行位置 [32950, 41188)，共 8,238 条。
- 行号以去除 CSV 表头后的 0-based 位置为准。
- 指标优化、模型选择、修复、阈值选择只能用 train/validation。
- 测试数据留给最终独立 evaluator；生成器与沙箱不挂载测试标签。
- 最终测试集只在方案、提示词、阈值与代码冻结后用于一次发布评估。若根据结果继续开发，必须披露测试已经被使用，不能再宣称其是从未见过的最终留出集。
- 一般 EDA 可以记录全数据标签数量；本次人工基线没有计算最终测试性能。开发阶段真正的隔离权限尚待实现，文件现阶段仍在本地 raw 目录。
- 官方数据有 12 条完整重复行；先审计，不能仅因业务特征相同就认定同一人。补充报告跨集合精确重复与去重敏感性分析，不隐瞒数据局限。

若主时序结果偏低，要如实展示漂移、可用特征少和时间外泛化的困难。随机分层切分可以作为另一个清楚标识的补充协议，不能与主协议混排候选结果。

## 4. SMS 划分

1. UTF-8 读取，每行只按首个 tab 切分标签和原文本，避免引号解析吞行。
2. 生成用于分组的“大小写归一化 + 连续空白折叠”哈希，模型输入仍用原文本。
3. 同哈希但标签冲突的组隔离审查。本次未发现冲突组。
4. 主协议每个规范化组保留第一条，排序组 ID 后，用 seed=42 分层切成 60/20/20。
5. 本次有效组划分为 3,095 / 1,032 / 1,032。训练词表、TF-IDF 的 IDF 和调参均不接触验证/测试拟合。
6. 报告正类是 spam；不能把所有样本判 ham 后用较高 accuracy 充当成功。
7. 不声称简单哈希解决了全部近重复问题；可增加近重复模板分析作为敏感性检查。

原始短信可能含电话号码等文本；演示只显示脱敏摘要。发送到外部 LLM 的是 schema、统计与少量脱敏例子，不上传整个数据集。

## 5. 能力知识从哪里来

知识库与行业数据集是两种东西，需要分别构建：

| 来源 | 抽取内容 | 验证方法 |
|---|---|---|
| UCI 字段说明 | 输入语义、正类定义、缺省标记、时间与泄漏限制 | 对照下载包的 names/readme 与实际列 |
| scikit-learn 官方文档 | Pipeline、列处理、未知类别、AP、概率输出的用法 | 文档定位 + 最小可运行检查 |
| scikit-learn 真实代码仓库 | import、函数/类、签名、源文件、依赖、docstring 元信息 | AST 静态解析，禁止执行被摄取代码 |
| 本项目人工基线 | 已验证实现与适用前提 | 标注 manual baseline，不冒称 Agent 生成 |
| Agent 运行与修复 | 失败类型、修复建议、验证结果、资源开销 | 来自确定性 runner 的结果，不直接相信模型自述 |
| 业务约束说明 | 可用字段、预算、输出要求 | 明确是本项目设计材料，不伪装成银行内部文件 |

建议第一版构建 12–20 张能力卡，例如混合类型预处理、未知类别推理、二分类概率接口、AP 指标、不平衡排序、禁用通话时长、TF-IDF 文本分类、稀疏矩阵兼容、超时停止、错误修复和模型持久化隔离。

至少 30 条抽取字段/关系人工标注作为小型核验集。它们可来自多篇文档和代码片段，但统计单位要写清楚，不能把 30 个字段写成 30 个独立能力。报告字段正确率、关系 precision/recall、出处有效率和失败例子。

真实代码候选：examples/compose/plot_column_transformer_mixed_types.py、examples/text/plot_document_classification_20newsgroups.py、sklearn/metrics/_ranking.py。优先固定 tag 对应 commit 和源码 SHA256；证据以实际可访问的文件为准。只抽取来源元信息与必要片段，保留 BSD-3-Clause 归属，避免复制整套第三方项目。

## 6. 摄取、冲突与回写协议

流程：读取受信来源清单 → 文档/AST 解析 → 源片段定位 → LLM 提取候选结构 → schema 校验 → 证据链接核对 → 人工抽检 → draft 入库 → 测试通过后提升状态。

每条事实记录 source_id、内容哈希、路径与行区间或章节、抽取版本、时间、置信度及适用前提。LLM 的置信度不是事实正确率。没有来源的推断必须标为 inferred，不能直接变成硬约束。

冲突不覆盖：保留多条带出处的 assertion；优先来源版本一致且本地验证成功的记录，无法解决时交给明确的约束策略或人工确认。失败建议先以 proposed 状态存储，复测成功才标为 validated；记录适用任务、依赖版本和失效条件，防止错误经验污染后续检索。

## 7. 数据制品与版本

最终应保存 dataset manifest、archive SHA256、解析版本、字段策略版本、split manifest、各集合行 ID 哈希、依赖锁文件与随机种子。能力记录引用的是 dataset_version + split_version + feature_policy，而不是笼统写“在 Bank 数据上验证过”。

下载失败时用已核验本地缓存；哈希不一致时 fail closed，提示人工检查来源更新。演示包提前准备已核验缓存，确保现场不依赖网络。不要自动换成未核验镜像或伪造数据。
