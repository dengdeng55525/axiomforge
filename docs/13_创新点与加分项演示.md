# 创新点与加分项演示

本页把题目的加分项连接到可运行命令、代码入口与验证证据。所有命令均在完成 README 环境安装、激活项目虚拟环境后，从仓库根目录执行。真实指标以保存的报告为准，Mock、历史分析与新模型调用分别标记。

## 1. 固定版本的仓库能力抽取

新增的 ingest-repo 面向已经下载的 Git 仓库。操作者明确选择 Python 文件、来源地址、许可证和适用任务；系统读取提交中的 Git blob，不导入或执行来源代码，也不检查工作区副本来代替提交快照。

以下用本项目的真实指标模块演示，可替换为另一个已审核的本地仓库及其 GitHub 来源地址：

~~~bash
python -m capability_factory ingest-repo . \
  --revision HEAD \
  --path src/capability_factory/metrics.py \
  --repository-url https://github.com/dengdeng55525/algorithm-capability-factory \
  --license MIT \
  --task-type tabular_binary_classification \
  --task-type text_binary_classification \
  --output artifacts/ingestion/repository.json
~~~

输出包括固定 commit、文件 blob ID 与 SHA256、符号行号、签名、返回注解、docstring、导入语句、能力卡和解析问题。manifest 的内容进入 SQLite，形成 Source → Capability 的来源关系和 Environment 依赖关系，可在知识探索中搜索函数名。

- 支持顶层函数、异步函数、类和类方法；不会推断运行时动态调用关系。
- 导入语句是静态依赖观察，不等于解析完成的 pip 版本锁文件。
- 任务适用性、来源 URL 和许可证由操作者声明，未经过自动法律或语义认证。
- 每次最多 50 个显式 Python 文件、单文件 256 KiB、总计 2 MiB、200 个符号；拒绝路径穿越和符号链接。
- AST 解析失败进入 issues；不会把没有抽取出的符号列作成功。
- Git 命令设置超时，不使用来源代码、Git hooks、替换对象或懒加载下载。

**版本演示**：对相同 commit 重复导入，new_capability_versions 为 0；在原仓库提交修改后再次导入，稳定能力 ID 对应新的版本和 SUPERSEDES 边，旧来源与旧版本仍可查看。抽取只产生 extracted 状态，不能绕过后续算法验证。

公开样例：[repository.json](../examples/evidence/innovation/repository.json)。该样例来自本项目真实 Git 快照，不是伪造的第三方业务仓库。

## 2. 有界多角色搜索与可复用失败经验

~~~bash
python -m capability_factory run \
  --provider local_http --dataset bank --search beam \
  --max-candidates 6 --max-repairs 2 --max-seconds 900 \
  --description '预测银行定期存款订购，仅使用通话前特征，禁止 duration。比较候选并搜索参数变体，输出验证、设计依据、资源与失败修复记录。'
~~~

没有运行本地模型时可选择 deepseek；工程测试可选择 mock，报告会保留模式标签。以上角色由同一个后端模型串行承担，各角色具有独立上下文和合约，并非单次提示直接交付代码。

解释器 → 证据检索 → Planner → Coder → 独立验证器 → Reviewer / Repair Coder → 再验证 → Curator → 版本化知识回写。

检查同一运行的以下证据：

| 设计机制 | 观察位置 | 应看到的事实 |
| --- | --- | --- |
| 证据约束规划 | candidate.plan.evidence_ids | 仅引用本次实际检索到的能力 |
| 有界扩展 | BEAM_EXPANDED、search_tree | 最多两个存活父节点，每个最多两个子节点，全局算法变体不重复 |
| 合约纠正 | RESPONSE_SCHEMA_REJECTED、PLAN_REJECTED | 格式和语义错误分别记录，不把模型文本直接当成合法计划 |
| 真实修复 | attempts、repairs、before_hash / after_hash | 修复后的不同代码重新执行同一验证器 |
| 经验沉淀 | knowledge_writeback.experiences | validated 对应成功修复证据，来源指向运行 |
| 后续可检索 | KnowledgeStore.search | 已验证经验可作为新任务的检索证据，保留任务范围与来源 |

一次真实本地运行已经发生非注入的重复构造错误，经审查和代码修复后通过，形成 1 条已验证经验。见 [预算、Beam 与修复证据](research/budget_beam_validation.json)。这证明闭环可执行，不能直接证明跨任务复用成功率或多角色相对单角色的统计优势；后者应使用 run_experiments.py 的消融配置和多次重复实验。

## 3. 质量与资源的 Pareto 分析

新运行把分析保存到 report.optimization。Web 报告新增“质量与资源权衡”，旧运行也可在 API 读取时获得带 analysis_version 的派生视图，原始存储记录不会因此被重写。

只分析已有报告，不产生 LLM 调用：

~~~bash
python -m capability_factory analyze-run RUN_ID \
  --output artifacts/resource-tradeoffs.json
~~~

**三个目标**：验证 AP 越高越好，训练耗时和 worker 峰值 RSS 越低越好。只有通过验证且三个测量值齐全、合法的候选进入计算；失败、缺失或非有限值列入 excluded，不能填 0 伪造免费候选。

一个候选在三个目标上均不差于另一个、并至少一项更好，才支配后者；不被任何候选支配的集合构成 Pareto 前沿。相同数值的候选不互相支配。父子节点额外输出 AP、训练时间和 RSS 的变化，便于解释搜索变体实际带来了什么。

这项分析不修改预注册的 AP 优先选择规则。每个候选只有一次资源观测，不能据此宣称稳定加速、p95 延迟或统计显著性；RSS 也不包含独立 LLM 服务的显存。跨数据集、机器或运行的性能结论需要单独的重复基准实验。

公开实测分析：[resource_tradeoffs.json](../examples/evidence/innovation/resource_tradeoffs.json)。其 run_id 指向已有真实本地模型报告，并明确是历史报告的派生分析。

新增的 [本地 14B 短信运行](../examples/evidence/sms_local_resources/report.json)直接在工作流中保存分析结果：两个候选均通过，选中 ComplementNB 的验证 AP 为 0.9598。公开目录同时包含每个候选的实际生成代码、验证记录、哈希清单和可读 HTML 报告；它与银行运行共同展示表格/文本场景复用同一编排。

## 4. 自动生成接口文档

~~~bash
python -m capability_factory export-openapi --output artifacts/openapi.json
~~~

导出内容来自实际 FastAPI 路由和 Pydantic schema；不读取模型凭证、不访问 LLM、不修改运行数据库。可交付给接口测试或客户端生成工具。启动 API 后也可使用 /docs 与 /openapi.json。

公开接口样例：[openapi.json](../examples/evidence/innovation/openapi.json)。现有部署文件见 deploy/，四卡本地模型启动配置见 configs/inference_profiles.json；导出接口不代表容器部署验收通过。

## 5. 加分项验收边界

- 安全执行：受限 AST 与资源限制进程已实现；任意 Python 的容器/微虚机隔离仍属于后续工作。
- 跨场景：bank 与 sms 共享框架，但各自保留固定切分和特征协议，不把新行业任务自动宣称为已支持。
- 可解释性：展示设计理由、来源和真实检查事实；不输出或依赖模型的私有思维链。
- 多卡：API/本地模型可切换，1 卡和 4 副本配置可用；本次功能增强不构成多卡吞吐或故障恢复基准。
- 完成证据：以 [增强验收记录](research/innovation_validation.json)、测试和公开制品为准。未完成的功能不能仅凭 README 描述视为交付。
